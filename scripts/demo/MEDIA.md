# RecoSocial demo media provenance

The versioned fixture folder is `public/demo/recosocial-v1/`. Its ten SVGs and one silent WebM are project-authored geometric visuals for development and clearly identified demo accounts. No scraped photographs, recognizable people, brand logos, third-party artwork, external fonts, or remote resources are used. These assets are synthetic examples, not representations of real users or real events.

## Static illustrations

`scripts/demo/generate-media.mjs` contains the complete source for ten original category illustrations: fitness (`health-fitness`), travel, gaming, technology, cars (`cars-bikes`), food, fashion, photography, music, and sports. Each 800 × 1000 SVG visibly says **GENERATED DEMO CONTENT** and **DEMO / NOT A REAL ACCOUNT**, and has an accessible title and description.

Run from the repository:

```sh
node scripts/demo/generate-media.mjs
```

This dependency-free command accepts no arguments, writes only the ten fixed filenames beneath `public/demo/recosocial-v1/`, and does not call a server or touch a database. Running it again produces identical SVG bytes. It preserves the existing video and any other files. Tests compare the generated bytes with the committed files and reject unexpected SVG assets, active markup, external resources, or a changed video hash.

## Silent video

`loop.webm` was generated for RecoSocial's M5 local browser fixture, using the project's own Canvas 2D shapes: a geometric sun, mountain and moving line. The original local development generator was the `/__generate` route in the M5 `local-backend.cjs` scratch harness; it recorded a 480 × 720 canvas using `canvas.captureStream(12)` and browser `MediaRecorder` with VP8. It did not use a camera, microphone, external media or internet resources. Its reviewed source has been preserved as the standalone `scripts/demo/reproduce-video.html` page, replacing the original local upload with an explicit download.

- Checked-in file: **19,920 bytes**; approximately **1.425 seconds** of silent VP8 WebM.
- SHA-256: `32391c925f0c44b358ed4de7eeab192a52873e3e408c11bb4fd36a1a16a2728e`.
- The byte-stable committed clip is reused by demo Reels. Re-recording produces the same scene, but browser encoding/timing can change bytes and duration; it is not a byte-deterministic regeneration promise.
- Open `scripts/demo/reproduce-video.html` in a browser with VP8 `MediaRecorder` support, select **Generate clip**, then **Download generated clip** to create a replacement locally. The page forbids network connections with Content Security Policy, cleans up recording tracks and object URLs, and is not shipped as an application route.
- The abstract clip has no burned-in demo wording; the seed's account names, biographies and captions must identify its synthetic context. It must not be used to imply a real user posted real footage.

## Maintenance policy

Keep this folder small and versioned. Adding media requires verified ownership or explicit reusable licensing and an updated provenance record. Do not fetch random image/video URLs, scrape social services, or embed third-party resources. Fixture URLs are served as static project assets; they do not require or bypass Storage permissions. The separately documented seeding process owns database changes and its development/demo-only safeguards.
