## Required decisions before live rollout

1. Inventory and back up the existing project; do not assume the repository describes current live state. Storage must be preflighted before applying the first clean-install migration: the two SQL files commit separately.
2. Resolve actual schema/history differences and write a separate reviewed forward migration. Existing private flags/media URLs require an explicit data/product decision; M1 did not convert or expose existing records automatically.
3. Validate the migration and application together on an isolated copy. Application code now depends on the new RPCs and notification triggers; deploying it ahead of compatible database definitions can break onboarding, counts and notifications.
4. Obtain explicit approval for the specific live migration/deployment, with recovery steps and test evidence. No deployment is part of this M1 commit.

Still outside the M1 proof: actual hosted policies, Auth delivery, Storage HTTP behavior, PostgREST joins, Realtime, true concurrent sessions, browser journeys and media lifecycle cleanup. Full private accounts require follow approval and protected media delivery in a separately approved milestone. Public media is intentionally retained.
